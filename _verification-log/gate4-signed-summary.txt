## Real bugs found and fixed during this verification (not hypothetical)

1. **Missing UTF-8 BOM in .ps1 scripts** — inherited from the original source pack, present
   before this consolidation. Windows PowerShell 5.1 fails to parse the box-drawing/emoji
   characters in BOM-less UTF-8 files. Fixed: re-saved init.ps1, scaffold-project.ps1,
   install-playwright-agents.ps1 with a UTF-8 BOM. Verified via static parse + real dry-run.
2. **JSON files written with a BOM** — `Set-Content -Encoding UTF8` in Windows PowerShell 5.1
   writes a BOM, which broke strict JSON.parse on the generated qa-state.json. Fixed: switched
   to `[System.IO.File]::WriteAllText`, which is BOM-free by default in .NET. Verified: fresh
   dry-run output has no BOM and parses cleanly with Node's JSON.parse.
3. **playwright.config.ts outputDir collision** — no explicit `outputDir` meant Playwright
   defaulted to `test-results/`, the same folder the project keeps its hand-authored
   test report in. The first real test run in this session deleted that report as a direct
   consequence — caught immediately by checking file survival, not assumed. Recovered
   byte-identical from the archive (diff-verified), then fixed by isolating Playwright's
   own output to `test-results/.playwright-artifacts`. Re-verified with a second full run:
   report survived.
